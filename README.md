# Плейбук кейсов — Егор Холов

Один самодостаточный лендинг со всеми кейсами.

**Смотреть:** <https://mrkholov.github.io/kholov-playbook/>

Локально открывается двойным кликом по `index.html` — без сервера и без интернета
(шрифты подгружаются с Google Fonts, без них подставляется системный).

```
kholov-playbook/
├── index.html            весь лендинг: разметка, стили и скрипты в одном файле
├── assets/img/           55 изображений, webp, 4,0 МБ, пропорции исходников сохранены
└── scripts/
    ├── extract-images.py вытаскивает картинки из pptx и пережимает в webp
    └── nbsp.py           расставляет неразрывные пробелы в русском тексте
```

## Что внутри

30 кейсов в восьми секциях: гейминг и киберспорт, инфлюенсеры и стримеры, измерение охватных
каналов, перформанс и продукт, события и контент, команда и P&L, что не сработало, рекомендации
и контакты. Перед секциями — карточки трёх компаний.

Winline-специфичного контента здесь нет: лендинг универсальный, под любую вакансию и любой созвон.

## Мелочи, которые перенесены из питча Winline

- Фото в шапке круглой аватаркой и крупным портретом в контактах — `assets/img/egor-kholov.webp`.
- Выделение ключевой фразы: `<span class="hl">…</span>`. В обычном тексте подложка оранжевая,
  внутри оранжевого блока `.why` — тёмная. Знак препинания после фразы забирается внутрь `span`,
  иначе между выделением и запятой остаётся дырка от паддинга.
- Подсветка пункта меню, чей раздел сейчас на экране. Скрытые фильтром разделы пропускаются,
  у самого низа страницы горит последний пункт.
- Неразрывные пробелы — скрипт ниже.

## Подборки

Кнопки вверху переключают, какие кейсы показаны. Разделы, где после фильтрации не осталось
ни одного кейса, скрываются целиком.

| Подборка | Что показывает |
|---|---|
| Все кейсы | 30 кейсов |
| Киберспорт и гейминг | активация со скинами, спонсорские спецпроекты, реактивация, персонализация |
| Беттинг и медиа | измерение, фрод, пост-вью, инфлюенсеры, неденежные награды |
| EdTech и e-commerce | перформанс, цены, воронки, вебинары, соцсети |
| Директорская роль | команда, P&L, найм, международный опыт, измерение |

Подборка задаётся тегами в атрибуте `data-tags` у каждого `<article class="case">`.
Теги: `esports`, `gaming`, `betting`, `edtech`, `perf`, `measure`, `influence`, `events`, `brand`, `lead`.
Чтобы кейс попал в новую подборку — допишите тег в `data-tags` и добавьте кнопку в блок `.filterbar-in`.

## Как переносить кейсы в другие материалы

**Текст в презентацию или письмо.** Кнопка «Скопировать» справа от заголовка кейса кладёт
в буфер весь его текст без подписей к картинкам — заголовок, цифры, буллеты, вывод. Готово
для вставки в слайд.

**Блок целиком в другой HTML.** Скопируйте `<article class="case">…</article>` и приложите
классы из `<style>`: `.case`, `.eyebrow`, `.lede`, `.metrics`, `.metric`, `.bul`, `.cards`,
`.card`, `.why`, `.note`, `.shots`, `.shot`. Палитра задана переменными в `:root`.

**В питч Winline** (`winline-cyber-brief/Winline Pitch v2.dc.html`). Палитра и шрифты те же:
фон `#0A0A0C`, текст `#F2F1EE`, акцент `#FF6A1A`, Golos Text и JetBrains Mono. Разница
в способе стилизации: в питче стили инлайновые, здесь — классы. Два пути:

1. Скопировать блок `<style>` из этого файла в `<helmet>` питча, дальше вставлять кейсы как есть.
2. Вставлять только текст кейса и оформлять его разметкой питча.

Картинки при переносе положите в `winline-cyber-brief/assets/` и поправьте пути в `src`.

## Картинки

Все изображения — webp, максимальная ширина 1500 px, качество 82. Ни одно не растянуто
и не обрезано. Клик по картинке открывает её целиком.

Галерея выровнена по рядам: у каждой `<figure class="shot">` в атрибуте `style` записано
`--ar` — пропорции этой картинки. Ширина карточки в ряду считается из `--ar`, поэтому в одном
ряду соседствуют фото разного размера, высота ряда общая, а пустых мест не остаётся.
Значения `--ar` проставляются скриптом из реальных размеров файлов, вручную их считать не нужно.

Блок спонсорских спецпроектов собран иначе: `.proj` — ряд, где крупное фото стоит рядом
со своим текстом, стороны чередуются. Так каждый проект идёт со своей картинкой.

Ни одна картинка не растягивается на всю колонку. У `<figure class="shot">` есть класс `cap`:
ширина по умолчанию 860 px — как у текстовой колонки, — а `--w` в `style` задаёт свою, если
исходник уже: `style="--ar:8.209;--w:706px"`. Шире исходника картинка не показывается никогда.
Клик открывает её целиком — мелкие цифры в таблицах читаются там.

Добавить новые из презентации:

```bash
python scripts/extract-images.py
```

Внутри скрипта — словарь `MAP`: имя файла в pptx → осмысленное имя на выходе. Путь к исходной
презентации и папке назначения задан в начале файла.

В `assets/img/` лежат 6 изображений про запас, они пока не вставлены в лендинг:
`back-to-past-crew`, `back-to-past-film`, `back-to-past-level`, `back-to-past-scene`,
`navigator-map`, `tiktok-portrait`.

## Публикация

**GitHub Pages — основная ссылка.** Отдаётся прямо из `main`, папка `/`. Любой пуш в `main`
обновляет страницу через минуту-другую:

```bash
git add -A && git commit -m "..." && git push
```

**Артефакт — запасной вариант**, если нужна ссылка без GitHub:

```bash
python scripts/build-artifact.py
```

Скрипт собирает `artifact.html` — тот же лендинг, но в одном файле: картинки вшиты в разметку
как data-URI, внешняя обёртка снята, единственный внешний ресурс — шрифты Google. Около 5 МБ
при лимите 16. Текущая версия: <https://claude.ai/code/artifact/dfa5bc87-1466-44a8-8369-584718ba11e9>
(приватная, пока не открыта через меню «Поделиться»). Файл в `.gitignore`: это сборка, а не исходник.

## Неразрывные пробелы

После правок текста прогоняйте:

```bash
python scripts/nbsp.py index.html
```

Прогонять надо и после правки текста, и после вставки новых `<span class="hl">`.

Скрипт работает только с текстовыми узлами: содержимое тегов, `<script>` и `<style>` не трогает,
запускать можно сколько угодно раз подряд.

## Источники цифр

Резюме (`CV - Marketing Director`), мастер-плейбук (`kholov-master-playbook.pptx`) и старая
колода с картинками (`Playbook - Egor Kholov.pptx`).

Там, где цифры расходились между источниками, взят вариант из мастер-плейбука как самый поздний
и самый защищаемый: бюджет Wargaming — `$1M+` в месяц, а не `$1,7M`; выручка EBAC — `$550K`
на пике; команда — 19 человек в прямом подчинении и до 30 в матричной; антифрод — `−$27K`
в месяц; кейс со скинами — троекратное снижение стоимости игрока по когорте и ~400 игроков
за 3 месяца пилота.

Телефоны рекомендателей не публикуются: люди не давали согласия, а лендинг разойдётся дальше,
чем планируется. В блоке указаны имена, должности и строка «контакты предоставлю по запросу».

Личный телефон с лендинга тоже снят — страница лежит в публичном репозитории и индексируется.
В контактах остались телеграм, почта и LinkedIn.
